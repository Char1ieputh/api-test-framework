# 接口安全测试检查清单

> 用途：面试讲"接口安全测试"时的配套材料，也可作为实际工作中的检查表。
> 用法：测一个接口时逐条过，命中问题就提缺陷。

---

## 一、身份认证

| 编号 | 检查项 | 测试方法 | 期望结果 |
|---|---|---|---|
| A1 | 无凭证访问 | 不带 `Authorization` 头直接请求 | 返回 401 |
| A2 | 无效 Token | 用伪造/过期的 Token 请求 | 返回 401 |
| A3 | Token 格式错误 | 去掉 `Bearer ` 前缀或改成其他类型 | 返回 401 |
| A4 | Token 过期 | 用已过期 Token 请求 | 返回 401，且不泄露内部信息 |
| A5 | 越权访问 | 用 A 用户 Token 访问 B 用户数据 | 返回 403 或数据隔离 |
| A6 | 水平越权 | 修改请求中的用户 ID 为他人 ID | 拒绝或仅返回本人数据 |
| A7 | 垂直越权 | 普通用户调用管理员接口 | 返回 403 |

## 二、参数篡改（重点）

| 编号 | 检查项 | 测试方法 | 期望结果 |
|---|---|---|---|
| B1 | 修改关键 ID | Fiddler 断点拦截，改订单/用户 ID 后放行 | 服务端应校验归属，拒绝非法访问 |
| B2 | 修改金额 | 篡改价格、金额类字段 | 服务端应二次校验，以服务端计算为准 |
| B3 | 修改数量为负数 | 下单数量改为 `-1` 或 `0` | 返回 400 |
| B4 | 修改状态字段 | 篡改订单状态、审核状态 | 服务端不接受客户端传入的状态 |
| B5 | **缺少防篡改签名** | 篡改参数后服务端直接接受 | **存在安全隐患：应增加签名校验** |
| B6 | 重放攻击 | 重复发送同一个合法请求 | 应有 nonce / 时间戳防重放 |

> **B5 就是本框架作者实际发现的缺陷**：篡改请求参数后服务端直接接受，
> 说明接口缺少参数完整性校验（签名机制）。

## 三、输入校验

| 编号 | 检查项 | 测试方法 | 期望结果 |
|---|---|---|---|
| C1 | SQL 注入 | 参数填入 `' OR '1'='1` | 被拦截或参数化处理，不报数据库错误 |
| C2 | XSS 注入 | 参数填入 `<script>alert(1)</script>` | 存储与回显均被转义 |
| C3 | 命令注入 | 参数填入 `; ls` / `\| whoami` | 被拦截 |
| C4 | 路径穿越 | 参数填入 `../../etc/passwd` | 被拦截 |
| C5 | 超长输入 | 传入 10000 字符 | 返回 400，不 5xx |
| C6 | 特殊字符 | 传入 `!@#$%^&*()` | 正常处理或明确报错 |
| C7 | 参数类型错误 | 该传数组传字符串 | 返回 400 |

## 四、信息泄露

| 编号 | 检查项 | 测试方法 | 期望结果 |
|---|---|---|---|
| D1 | 报错信息泄露 | 构造异常请求触发报错 | 不返回堆栈、SQL、内部路径 |
| D2 | 敏感字段返回 | 查看响应体 | 不返回密码、密钥、内部 ID |
| D3 | 接口枚举 | 遍历 ID 查看是否可批量拉取数据 | 应有频率限制 |
| D4 | 调试接口暴露 | 尝试访问 `/debug`、`/actuator` | 生产环境应关闭 |

## 五、传输与频率

| 编号 | 检查项 | 测试方法 | 期望结果 |
|---|---|---|---|
| E1 | 是否强制 HTTPS | 用 HTTP 访问 | 应重定向到 HTTPS |
| E2 | 敏感信息加密 | 抓包查看请求体 | 密码等字段应加密传输 |
| E3 | 暴力破解防护 | 连续错误登录 | 应有验证码 / 锁定 / 限流 |
| E4 | 接口限流 | 短时间高频请求 | 应返回 429 或限流提示 |

## 工具说明

| 工具 | 用途 |
|---|---|
| **Fiddler** | 抓包、断点拦截、篡改请求参数 |
| **Postman** | 构造异常请求、批量遍历参数 |
| **浏览器 F12** | 查看请求头、Cookie、响应体 |

### Fiddler 篡改参数的操作步骤

1. 打开 Fiddler，开启抓包（`Capturing`）
2. 找到目标请求，右键 → `Copy` → `Just Url`，确认抓得到
3. 设置断点：菜单 `Rules` → `Automatic Breakpoints` → `Before Requests`
4. 在目标页面触发请求，Fiddler 会拦截
5. 在 `Inspectors` → `Raw` 里**修改请求参数**
6. 点 `Run to Completion` 放行
7. 观察响应：**如果服务端接受篡改后的参数并正常返回，说明缺少校验**

## 缺陷报告模板

```
缺陷标题：【接口名】篡改 XX 参数后服务端未校验，存在 XX 风险
严重程度：高
前置条件：已获取合法登录态
复现步骤：
  1. 打开 Fiddler，开启 Before Requests 断点
  2. 在页面执行 XX 操作，触发 XX 接口请求
  3. 拦截请求，将参数 XX 从 A 改为 B
  4. 放行请求
预期结果：服务端应校验参数完整性，拒绝篡改后的请求（返回 4xx）
实际结果：服务端直接接受篡改参数并正常返回数据
影响分析：攻击者可绕过 XX 校验，造成 XX 后果
修复建议：增加参数签名校验；关键字段以服务端数据为准，不信任客户端传值
```
